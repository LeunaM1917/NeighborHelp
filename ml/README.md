# NeighborHelp algorithm training

These offline tools produce reproducible candidates and metrics. They never replace `LSTM_train/neighborhelp_lstm_sentiment.keras`, change the app's ranking weights, deploy a service, or edit the academic paper.

## Environment

Use a virtual environment and the same TensorFlow/Keras runtime as the sentiment API:

```powershell
py -3.13 -m venv ml/.venv
ml/.venv/Scripts/python.exe -m pip install -r ml/requirements.txt
```

The training tools otherwise use the standard library and NumPy. Training uses two CPU threads by default and does not require a CUDA installation. Datasets and checkpoints under `ml/data` and `ml/runs` are ignored by Git. Keep the source manifests and attribution files with any research results or redistributed derivatives.

## Sentiment

```powershell
python -m ml.prepare_firecs
python -m ml.sentiment_train --data ml/data/firecs/reviews.csv --output ml/runs/firecs-new-run --source "FiReCS human labels, CC BY 4.0" --languages "English,Tagalog/Taglish" --epochs 6
```

For additional human-labeled English reviews:

```powershell
python -m ml.prepare_bilingual
python -m ml.sentiment_train --data ml/data/bilingual/reviews.csv --output ml/runs/bilingual-new-run --source "FiReCS and DynaSent round 1, human labels, CC BY 4.0" --languages "English,Tagalog/Taglish" --epochs 6
```

FiReCS is pinned to revision `4da2863e53e7260ab6f2dcd2089af5c112d25c80` and DynaSent to `707b6208978bfe7ff251a0c3263c9f0552c27b48`. Source manifests record checksums, row counts, sources, licenses, sampling and overlap removal. DynaSent uses human `gold_label` values; star ratings and model predictions are never used as sentiment labels. Only original three-class records are kept.

Both preparation commands preserve official test partitions and remove training overlap. Validation comes only from original training data when a source has no validation partition. The extended experiment reuses the FiReCS test previously examined in the initial pilot; the manifest explicitly records that limitation. Training chooses stopping by validation loss, then evaluates the test partition. The original model's training data is unknown, so its prior exposure to public benchmarks cannot be ruled out.

For your own data use `text,label` plus optional `group_id,split,source,language`. Labels must explicitly be `negative`, `neutral`, `positive`, or the corresponding `0,1,2`. Exact normalized duplicates are removed, conflicting duplicate labels are quarantined, and duplicates or groups crossing explicit partitions stop training. Automatic splits are deterministic grouped 60/20/20 splits, not stratified splits. Each partition must have at least ten examples per class.

The model is a raw-string-input BiLSTM. Its vocabulary is adapted on training data only. `--mode finetune` instead trains the Dense classification layers of a supplied existing raw-string model while keeping its base and preprocessing fixed. Output includes `model.keras`, `model.metadata.json`, training history, source/checkpoint hashes, and accuracy, macro F1, per-class precision/recall, confusion matrix and calibration metrics. Models are always marked unapproved for production until domain and language validation is complete.

An independent word/character TF-IDF logistic regression comparison is also available:

```powershell
python -m ml.sentiment_linear_train --data ml/data/bilingual/reviews.csv --output ml/runs/linear-new-run --source "FiReCS and DynaSent round 1, human labels, CC BY 4.0" --languages "English,Tagalog/Taglish"
```

It fits vocabulary/IDF on training only, selects regularization from validation macro F1, and writes `model.joblib` plus metadata and test metrics. Compare architecture choices on the same validation data. The API can serve this candidate by setting `SENTIMENT_MODEL_PATH` to `model.joblib`; responses explicitly identify `model_family=tfidf_logistic`. Only load joblib files generated by a trusted local training run. Default production builds still use the existing LSTM.

`unicode_v1` preprocessing preserves Philippine-language letters. The API reads the adjacent metadata file so training and serving use the same cleaner and class order. Without metadata, existing models continue to use their original ASCII cleaner. `SENTIMENT_MODEL_PATH` can point to a candidate for local review; no production path is changed by training.

Example local candidate evaluation:

```powershell
$env:SENTIMENT_MODEL_PATH = (Resolve-Path ml/runs/firecs-new-run/model.keras).Path
python -m uvicorn main:app --app-dir sentiment_api --host 127.0.0.1 --port 8000
```

The Dockerfile supports optional build arguments `SENTIMENT_ARTIFACT_DIR=ml/runs/firecs-new-run` and `SENTIMENT_MODEL_FILENAME=model.keras` for a reviewed candidate. Default builds still use the original `LSTM_train` directory. Building and deploying are separate actions.

## Provider matching

Haversine proximity is calculated, not learned. The offline tuner learns only the relative weights of proximity, Bayesian rating, availability and completion from independent relevance grades. It reproduces the application's cold-start priors. It does not learn eligibility or turn an unqualified provider into a qualified one.

The fitter minimizes pairwise logistic loss on training requests, selects regularization on validation NDCG@5 and evaluates the fixed candidate on held-out requests. Weights must sum to one and stay between 5% and 75% so every stated factor remains represented. Reports compare the candidate with 40/30/20/10 using NDCG@5, pairwise agreement and agreement with the highest human grade. Near-tie randomization is excluded from deterministic offline metrics. Baseline production weights remain unchanged.

See [labeling instructions](labeling/README.md) and fill the packet before training. The tool rejects unlabeled examples. It can be rerun after genuine pre-outcome snapshots or additional human judgments are collected.

## Validation

```powershell
python -m pytest ml/tests -q
python -m pytest sentiment_api/test_sentiment.py -q
```

ML unit tests use clearly synthetic fixtures to verify splitting, eligibility, metrics and fitting. These fixtures are not research evaluation results or production training data.
